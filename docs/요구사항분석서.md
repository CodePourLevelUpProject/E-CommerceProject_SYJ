## 1. 개요

### 1.1 목적

이 문서는 온라인 쇼핑몰 프로젝트의 요구사항을 정리한 문서입니다.

### 1.2 목표

1. **상품 목록 조회는 200ms 이내**
    1. 메인 홈 블록(인기/베스트/배너)과 상품 목록 (검색/카테고리) API의 응답 속도는 아래 기준을 준수하는 것을 목표로 합니다.
        - 서버 처리 시간 기준(백엔드에서 측정) : **p50 ≤ 80ms, p95 ≤ 200ms, p99 ≤ 350ms**
        - 사용자 체감 기준(브라우저에서 첫 바이트 수신까지) : **p95 ≤ 300ms**
        - 조건
            - 데이터 : 상품 10만 건, 카테고리 최대 3단계, 각 상품 썸네일 1장
            - 콜드 캐시 첫 호출 : **p95 ≤ 500ms**, 웜 캐시 상태: **p95 ≤ 200ms**
2. **주문 처리 속도는 1초 이내 (결제사 승인 제외)**
    1. 사용자가 “주문하기”를 눌러 주문서가 만들어지고 재고가 임시로 잡히기까지의 시간은 아래 기준을 준수하는 것을 목표로 합니다.
        - 서버 처리 시간 기준 : **p50 ≤ 120ms, p95 ≤ 1,000ms, p99 ≤ 1,500ms**
            - 측정 방법은 같은 주문 ID를 기준으로 묶어 측정합니다.
        - 포함 단계
            1. 장바구니 검증(가격/재고/옵션 변경 확인)
            2. 쿠폰·포인트 계산
            3. 주문/주문상품 레코드 생성
            4. **재고 예약(hold)** 레코드 생성(유지시간 TTL 10분)
            5. 결제 요청용 토큰/리다이렉트 URL 생성(외부 결제사는 **응답 시간에서 제외**)
3. **동시에 많은 사용자가 주문해도 재고가 잘못 빠지지 않기(오버셀 방지)**
    1. 오버셀에서의 정합성은 100%를 목표로 합니다.
    2. 대상 부하는 동일 SKU에 대해 100 TPS 동시 주문 상황으로 정합니다.

---

## 2.범위

- 포함: 메인 화면(인기/베스트 상품, 배너), 상품 검색/필터/정렬, 상품 상세/리뷰, 장바구니, 주문/결제, 배송 추적, 고객센터 게시판, 마이페이지, 관리자 페이지(간단 기능)
- 제외: AI 추천, 복잡한 쿠폰 정책, 해외 배송/다국어 지원

---

## 3. 사용자 권한

- 게스트(로그인 안한 사용자) : 상품 보기, 장바구니 담기 가능
- 회원 : 주문/결제, 리뷰 작성, 문의하기 가능
- 관리자 : 배너/공지/재고 관리, 게시글 관리 가능

---

## 4. 기능 요구사항

### 4.1 메인 화면

### 4.1.1 인기 상품 노출

- **상세 설명**: 웹사이트의 첫인상을 결정하는 메인 화면에 사용자의 구매를 유도할 수 있는 매력적인 상품 목록을 동적으로 노출합니다. 인기 상품, 베스트 상품 랭킹은 시스템에 의해 자동으로 집계되어야 합니다.
- **필요 데이터**
    - `상품(Product)`: `상품 ID`, `상품명`, `대표 이미지 URL`, `판매 가격`
    - `랭킹 데이터(RankingData)`: `상품 ID`, `판매량`, `조회수`, `평균 별점`, `리뷰 수`, `리뷰 작성 날짜`, `집계일`
- **사용자 스토리**
    - "나는 방문자로서, 메인 화면에서 요즘 가장 잘 팔리고 인기 있는 상품들을 한눈에 보고 싶다. 그래야 쇼핑 트렌드를 쉽게 파악하고 물건을 고를 수 있다."
- **완료 조건**
    1. **인기 상품 TOP 10**: 최근 7일간의 **(판매량 * 0.5) + (조회수 * 0.3) + (평점 * 0.2)** 공식(변경 가능성 존재)을 기준으로 상위 10개 상품을 집계하여 노출한다.
    2. **베스트 상품 TOP 10**: 누적 리뷰 수가 가장 많은 순서대로 상위 10개 상품을 노출한다. 동점일 경우, 최근 등록된 리뷰가 있는 상품을 우선 노출한다.
    3. 랭킹 데이터는 매일 자정에 배치(Batch) 작업을 통해 업데이트되어야 한다.
    4. 상품 이미지를 클릭하면 해당 상품의 상세 페이지로 이동해야 한다.

### 4.1.2 광고 배너 관리

- **상세 설명**: 마케팅 목적의 이벤트나 특정 상품을 홍보하기 위한 광고 배너 영역입니다. 관리자는 관리자 페이지에서 손쉽게 배너 이미지, 연결 링크, 노출 순서를 관리할 수 있어야 합니다.
- **필요 데이터**
    - `배너(Banner)`: `배너 ID`, `배너명`, `이미지 URL`, `연결 URL`, `점수(score)`, `노출 시작일`, `노출 종료일`, `활성 상태`
- **사용자 스토리**
    - "나는 마케터로서, 진행 중인 프로모션을 가장 눈에 잘 띄는 메인 화면 배너에 등록하고, 중요도에 따라 순서를 바꾸고 싶다."
- **완료 조건**
    1. 메인 화면에는 최대 5개의 배너가 캐러셀 형태로 자동 전환되며 노출된다.
    2. 관리자는 각 배너에 1부터 100까지의 점수(score)를 부여할 수 있으며, 점수가 높을수록 앞 순서에 노출된다.
    3. 배너 이미지를 클릭하면 관리자가 설정한 특정 URL(상품 상세, 이벤트 페이지 등)로 이동해야 한다.
    4. 배너 노출 기간(시작일, 종료일)을 설정할 수 있어야 하며, 기간이 아닐 경우 자동으로 비노출 처리된다.

### 4.1.3 카테고리 메뉴

- **상세 설명**: 사용자가 원하는 상품군에 쉽게 접근할 수 있도록 전체 상품 카테고리를 직관적인 구조로 제공합니다.
- **필요 데이터**
    - `카테고리(Category)`: `카테고리 ID`, `카테고리명`, `상위 카테고리 ID (Self-Join)`, `노출 순서`
- **사용자 스토리**
    - "나는 쇼핑객으로서, 상단의 카테고리 메뉴에서 '여성의류 > 상의 > 티셔츠'와 같이 원하는 상품 분류를 쉽게 찾아 클릭하고 싶다."
- **완료 조건**
    1. 마우스를 올렸을 때 하위 카테고리가 나타나는 드롭다운 또는 메가 메뉴 형식을 제공한다.
    2. 최대 3단계의 Depth(대분류-중분류-소분류)를 지원해야 한다.
    3. 카테고리 메뉴 클릭 시, 해당 카테고리에 속한 상품 목록 페이지로 이동해야 한다.

### 4.2 상품 카탈로그

### 4.2.1 상품 검색

- **상세 설명**: 사용자가 원하는 상품을 키워드를 통해 빠르게 찾을 수 있는 핵심 기능입니다. 초기에는 DB의 Full-Text Search를 활용하고, 서비스 규모 확장 시 Elasticsearch 같은 전문 검색 엔진으로 전환할 수 있도록 인터페이스 기반으로 설계합니다.
- **필요 데이터**
    - `상품(Product)`: `상품명`, `브랜드명`, `상품 설명`, `상품 태그`
- **사용자 스토리**
    - "나는 고객으로서, 검색창에 '나이키 운동화'라고 입력했을 때, 상품명이나 브랜드에 '나이키'와 '운동화'가 포함된 상품 목록을 보고 싶다."
- **완료 조건**
    1. 검색 결과는 기본적으로 정확도 순으로 정렬되어야 한다.
    2. 검색어 자동완성 기능을 제공하여 사용자 편의성을 높인다.
    3. 검색 결과가 없을 경우, "검색 결과가 없습니다."라는 메시지와 함께 추천 검색어를 제시한다. (선택)

### 4.2.2 상품 필터링

- **상세 설명**: 검색 결과나 카테고리 상품 목록에서 사용자가 원하는 조건에 맞는 상품만 추려볼 수 있도록 다양한 필터 옵션을 제공합니다.
- **필요 데이터**
    - `상품(Product)`: `브랜드명`, `판매 가격`, `평균 별점`, `재고 수량`
- **사용자 스토리**
    - "나는 '티셔츠' 목록에서 '나이키' 브랜드의 '5만원 이하'이면서 '평점 4점 이상'인 상품만 골라보고 싶다."
- **완료 조건**
    1. 브랜드, 가격 범위, 평점, 재고 유무 등 여러 필터를 동시에 적용(AND 조건)할 수 있어야 한다.
    2. 가격 필터는 사용자가 직접 범위를 입력하거나 가격대 슬라이더(Slider)(선택)를 통해 조절할 수 있어야 한다.
    3. 필터 적용 시, 페이지 리로드 없이 비동기적으로 상품 목록이 갱신되어야 한다.

### 4.2.3 상품 정렬

- **상세 설명**: 필터링된 상품 목록을 사용자가 원하는 기준에 맞춰 재정렬할 수 있는 기능을 제공합니다.
- **필요 데이터**
    - `상품(Product)`: `판매 가격`, `등록일`
    - `랭킹 데이터(RankingData)`: `인기 점수(또는 판매량)`
- **사용자 스토리**
    - "나는 검색된 상품 목록을 '낮은 가격순'으로 정렬해서 가장 저렴한 상품부터 확인하고 싶다."
- **완료 조건**
    1. '가격 낮은순', '가격 높은순', '인기순', '최신 등록순' 정렬 옵션을 드롭다운 형태로 제공한다.
    2. 정렬 기준 변경 시, 페이지 리로드 없이 비동기적으로 상품 목록이 갱신되어야 한다.
    3. 기본 정렬 값은 '인기순'으로 설정한다.

### 4.2.4 상품 상세 정보

- **상세 설명**: 사용자가 상품 구매를 결정하는 데 필요한 모든 정보를 상세하게 제공하는 페이지입니다.
- **필요 데이터**
    - `상품(Product)`: `상품명`, `대표 이미지 URL`, `상세 설명(HTML)`, `판매 가격`
    - `상품 이미지(ProductImage)`: `이미지 ID`, `상품 ID`, `이미지 URL`, `순서`
    - `상품 옵션(ProductOption)`: `옵션 ID`, `상품 ID`, `옵션명(예: 색상)`, `옵션값(예: 블랙)`, `추가 금액`, `재고 수량`
    - `리뷰 요약(ReviewSummary)`: `상품 ID`, `평균 별점`, `총 리뷰 수`
- **사용자 스토리**
    - "나는 구매자로서, 마음에 드는 상품의 큰 이미지를 보고, 원하는 색상과 사이즈를 선택한 후, 상세 설명을 읽고 구매를 결정하고 싶다."
- **완료 조건**
    1. 메인 이미지 외 여러 각도의 서브 이미지를 썸네일 형태로 제공하며, 클릭 시 메인 이미지가 변경되어야 한다.
    2. 색상, 사이즈 등 옵션 선택에 따라 추가 금액이 발생할 경우, 최종 가격에 즉시 반영되어야 한다.
    3. 옵션별 재고가 품절일 경우, 해당 옵션은 비활성화 처리되고 "품절"이라고 표시되어야 한다.

### 4.3 리뷰 시스템

### 4.3.1 리뷰 작성 권한

- **상세 설명**: 신뢰도 높은 리뷰 문화를 형성하기 위해, 실제로 해당 상품의 구매를 완료한 사용자에게만 리뷰 작성 권한을 부여합니다.
- **필요 데이터**
    - `주문 항목(OrderItem)`: `주문 항목 ID`, `회원 ID`, `상품 ID`, `주문 상태(예: 배송완료)`, `상태 변경 날짜`
    - `리뷰(Review)`: `리뷰 ID`, `주문 항목 ID` (리뷰 작성 여부 확인용)
- **사용자 스토리**
    - "나는 이 상품을 구매했기 때문에, 다른 사람들에게 도움이 되도록 내 경험을 바탕으로 리뷰를 작성하고 싶다."
- **완료 조건**
    1. '배송 완료' 상태로 변경된 후 7일이 지난 주문 건에 대해서만 리뷰 작성이 가능하다.
    2. 한 개의 주문 상품에 대해 한 번만 리뷰를 작성할 수 있으며, 작성 후에는 수정 및 삭제만 가능하다.

### 4.3.2 리뷰 내용

- **상세 설명**: 사용자가 상품에 대한 만족도를 다양한 형태로 표현할 수 있도록 별점, 텍스트, 사진 첨부 기능을 제공합니다.
- **필요 데이터**
    - `리뷰(Review)`: `리뷰 ID`, `회원 ID`, `상품 ID`, `별점`, `내용`, `작성일`
    - `리뷰 이미지(ReviewImage)`: `이미지 ID`, `리뷰 ID`, `이미지 URL`
- **사용자 스토리**
    - "나는 이 옷의 실제 색감을 보여주기 위해 직접 찍은 사진을 첨부하고, 별 5개와 함께 만족스러운 착용 후기를 남기고 싶다."
- **완료 조건**
    1. 별점은 필수 입력 항목이며, 1점부터 5점까지 선택할 수 있다.
    2. 사진은 최대 5장까지 첨부 가능하며, 각 파일의 크기는 10MB를 초과할 수 없다. (JPG, PNG 형식만 허용)

### 4.3.3 리뷰 관리

- **상세 설명**: 건전한 커뮤니티 환경을 위해 욕설, 비방, 광고 등 부적절한 내용이 포함된 리뷰를 관리자가 관리할 수 있는 기능입니다.
- **필요 데이터**
    - `리뷰(Review)`: `리뷰 ID`, `상태(예: 정상, 블라인드)`
    - `리뷰 신고(ReviewReport)`: `신고 ID`, `리뷰 ID`, `신고자 ID`, `신고 사유`
- **사용자 스토리**
    - "나는 관리자로서, 사용자로부터 신고가 접수된 부적절한 리뷰의 내용을 확인하고, 정책에 따라 다른 사용자에게 보이지 않도록 블라인드 처리하고 싶다."
- **완료 조건**
    1. 관리자는 신고된 리뷰 목록을 관리자 페이지에서 확인할 수 있다.
    2. 블라인드 처리된 리뷰는 작성자와 관리자에게만 보이며, 다른 사용자에게는 "관리자에 의해 블라인드 처리된 리뷰입니다."라는 메시지가 노출된다.

### 4.4 장바구니

### 4.4.1 장바구니 관리

- **상세 설명**: 사용자가 구매하고자 하는 상품들을 임시로 보관하고, 수량 조절 및 삭제 등 편집 기능을 제공하는 공간입니다. 장바구니 정보는 사용자가 로그인하지 않아도 유지되어야 하며(세션/로컬 스토리지 기반), 로그인 시 계정에 동기화되어야 합니다.
- **필요 데이터**
    - `장바구니 항목(CartItem)`: `장바구니 항목 ID`, `회원 ID(또는 세션 ID)`, `상품 ID`, `옵션 ID`, `수량`, `등록일`
- **사용자 스토리**
    - "나는 고객으로서, 마음에 드는 상품 여러 개를 장바구니에 담아두고, 최종 구매 직전에 각 상품의 수량을 늘리거나 줄이고, 일부 상품은 삭제하고 싶다."
- **완료 조건**
    1. 상품 상세 페이지에서 '장바구니 담기' 버튼 클릭 시, 선택한 옵션(색상, 사이즈 등)과 수량이 장바구니에 추가되어야 한다.
    2. 장바구니 페이지에서 각 상품별로 수량을 변경할 수 있는 입력 필드 또는 +/- 버튼이 제공되어야 하며, 변경 시 금액이 실시간으로 재계산되어야 한다.
    3. 개별 상품을 삭제할 수 있는 '삭제' 버튼과, 장바구니의 모든 상품을 비우는 '전체 삭제' 버튼이 있어야 한다.
    4. 로그인하지 않은 상태의 장바구니 상품은 브라우저를 닫았다 열어도 7일간 유지되어야 한다. 로그인 시 해당 계정의 장바구니와 합쳐져야 한다.

### 4.4.2 가격 계산

- **상세 설명**: 장바구니에 담긴 상품들의 총액과 예상 배송비, 그리고 적용 가능한 할인(쿠폰, 포인트)을 모두 계산하여 사용자에게 최종 결제 예정 금액을 명확하게 보여줍니다.
- **필요 데이터**
    - `상품(Product)`: `판매 가격`
    - `쿠폰(Coupon)`: `쿠폰 ID`, `할인 금액/율`, `최소 주문 금액`, `유효 기간`
    - `회원(User)`: `보유 포인트`
    - `배송 정책(ShippingPolicy)`: `기본 배송비`, `무료 배송 기준 금액`
- **사용자 스토리**
    - "나는 구매자로서, 장바구니에서 내가 가진 쿠폰을 적용하고 포인트를 사용했을 때 최종적으로 얼마를 결제해야 하는지 미리 확인하고 싶다."
- **완료 조건**
    1. '총 상품 금액', '배송비', '할인 금액', '최종 결제 예정 금액' 항목이 명확히 구분되어 표시되어야 한다.
    2. 배송비는 기본 배송비 정책(예: 5만원 이상 구매 시 무료)에 따라 자동으로 계산되어야 한다. (도서/산간 지역 추가 배송비 포함)
    3. '쿠폰 적용' 버튼 클릭 시, 해당 주문에 적용 가능한 쿠폰 목록이 팝업 또는 드롭다운으로 노출되어야 한다.
    4. 사용자가 보유한 포인트를 사용할 수 있는 입력 필드가 있어야 하며, '전액 사용' 버튼을 제공해야 한다.
    5. 쿠폰과 포인트는 중복 적용이 가능해야 한다.

### 4.5 주문/결제

### 4.5.1 주문 생성 및 재고 관리

- **상세 설명**: 사용자가 '주문하기' 버튼을 누르는 시점부터 결제가 완료되기까지의 과정입니다. 이 과정에서 다른 사용자가 해당 상품을 구매하지 못하도록 재고를 선점(예약)하고, 결제 결과에 따라 재고를 최종 차감하거나 복구하는 로직이 중요합니다.
- **필요 데이터**
    - `주문(Order)`: `주문 ID`, `주문번호`, `회원 ID`, `주문 상태(예: 결제대기, 결제완료)`, `총 결제 금액`, `주문일`
    - `주문 항목(OrderItem)`: `주문 항목 ID`, `주문 ID`, `상품 ID`, `옵션 ID`, `수량`, `가격`
    - `상품 옵션(ProductOption)`: `재고 수량`
- **사용자 스토리**
    - "나는 구매자로서, '주문하기'를 누른 상품이 결제하는 동안 다른 사람에게 팔리지 않도록 보장받고 싶다."
- **완료 조건**
    1. '주문하기' 클릭 시, 장바구니의 상품 정보로 주문서(Order Sheet)가 생성되고, 해당 상품들의 재고가 '예약' 상태로 변경되어야 한다. (실제 재고에서 차감)
    2. 결제가 성공적으로 완료되면, '예약' 상태의 재고가 '판매 확정'으로 변경되어야 한다.
    3. 사용자가 결제를 중간에 취소하거나, 결제 시스템 오류 등으로 실패할 경우, '예약' 상태였던 재고는 즉시 '판매 가능' 상태로 복구되어야 한다.
    4. 재고 예약은 10분의 유효시간을 가지며, 10분 내에 결제가 완료되지 않으면 주문은 자동 취소되고 재고는 복구된다.

### 4.5.2 주문 취소

- **상세 설명**: 사용자가 주문 상태에 따라 직접 주문을 취소할 수 있는 기능입니다. 배송이 시작된 이후에는 취소가 불가능하며, '반품' 절차로 전환됨을 안내해야 합니다.
- **필요 데이터**
    - `주문(Order)`: `주문 ID`, `주문 상태(결제완료, 배송준비중, 배송중 등)`
    - `결제 정보(Payment)`: `결제 ID`, `주문 ID`, `결제 수단`
- **사용자 스토리**
    - "나는 주문 직후 마음이 바뀌어서, 아직 배송이 시작되기 전이라면 마이페이지에서 간편하게 주문을 취소하고 싶다."
- **완료 조건**
    1. 주문 상태가 '결제 완료' 또는 '배송 준비중'일 때, 주문 상세 페이지에 '주문 취소' 버튼이 노출되어야 한다.
    2. '배송 중', '배송 완료' 상태에서는 '주문 취소' 버튼이 비활성화되고, '반품 신청' 버튼이 노출되어야 한다.
    3. 사용자가 주문을 취소하면, 결제된 금액은 자동으로 환불 처리(카드 결제 취소, 포인트 복구 등)되고 재고는 복구되어야 한다.

### 4.5.3 결제 처리

- **상세 설명**: PG(Payment Gateway)사와의 연동을 통해 안전하고 다양한 결제 수단을 사용자에게 제공합니다.
- **필요 데이터**
    - `결제 정보(Payment)`: `결제 ID`, `주문 ID`, `PG사 거래 ID`, `결제 수단`, `결제 금액`, `결제 상태`
    - `포인트 사용내역(PointHistory)`: `사용 ID`, `회원 ID`, `주문 ID`, `사용 포인트`
    - `쿠폰 사용내역(CouponUsage)`: `사용 ID`, `회원 ID`, `주문 ID`, `쿠폰 ID`
- **사용자 스토리**
    - "나는 신용카드, 휴대폰 소액결제, 카카오페이 등 내가 사용하기 편한 방법으로 결제하고 싶다."
- **완료 조건**
    1. 토스페이먼츠, KG이니시스 등 외부 결제 연동 모듈을 통해 결제가 처리되어야 한다.
    2. 신용카드, 가상계좌, 간편결제(카카오페이, 네이버페이 등) 결제 수단을 제공해야 한다.
    3. 포인트와 쿠폰 할인이 적용된 최종 금액으로 결제가 이루어져야 한다.

### 4.6 배송 추적

### 4.6.1 배송 정보 연동 및 상태 관리

- **상세 설명**: 관리자가 입력한 운송장 번호를 통해 택배사의 API와 연동하여 실시간 배송 현황을 조회하고, 이를 사용자에게 시각적으로 제공합니다.
- **필요 데이터**
    - `배송(Shipping)`: `배송 ID`, `주문 ID`, `택배사 코드`, `운송장 번호`, `배송 상태`
- **사용자 스토리**
    - "나는 내가 주문한 상품이 지금 어디쯤 오고 있는지, 언제쯤 도착할지 주문 내역 페이지에서 바로 확인하고 싶다."
- **완료 조건**
    1. 관리자가 관리자 페이지에서 주문 건에 대해 '송장 번호 입력'을 하면, 주문 상태가 '배송 중'으로 자동 변경되어야 한다.
    2. 주문 상세 페이지 내 '배송 조회' 버튼 클릭 시, 택배사 API를 호출하여 현재 배송 위치와 상태(집화, 간선상차 등)를 팝업 또는 페이지 내에 표시해야 한다.
    3. '결제완료 → 배송준비 → 배송중 → 배송완료'의 상태가 명확하게 관리되고, 각 단계 변경 시 사용자에게 이메일 또는 푸시 알림이 발송되어야 한다.

### 4.7 고객센터/게시판

### 4.7.1 문의 기능 (1:1 문의)

- **상세 설명**: 사용자가 서비스 이용 중 발생하는 궁금증이나 문제에 대해 관리자에게 비공개로 문의할 수 있는 기능입니다.
- **필요 데이터**
    - `문의(Inquiry)`: `문의 ID`, `회원 ID`, `문의 유형`, `제목`, `내용`, `상태(답변대기, 답변완료)`, `작성일`
    - `문의 답변(InquiryAnswer)`: `답변 ID`, `문의 ID`, `관리자 ID`, `내용`, `답변일`
- **사용자 스토리**
    - "나는 주문한 상품의 배송이 너무 늦어져서, 내 주문 번호와 함께 사진을 첨부해서 1:1로 문의하고 싶다."
- **완료 조건**
    1. 문의 유형(주문/결제, 배송, 상품, 기타)을 선택할 수 있어야 한다.
    2. 문의글 작성 시, 사용자의 주문 내역을 불러와 연결할 수 있는 기능이 제공되어야 한다.
    3. 관리자가 답변을 등록하면 문의글의 상태가 '답변 완료'로 변경되고, 사용자에게 이메일 알림이 발송되어야 한다.

### 4.7.2 공지사항

- **상세 설명**: 관리자가 모든 사용자에게 알려야 할 정보(이벤트, 시스템 점검, 휴무일 등)를 게시하는 공간입니다.
- **필요 데이터**
    - `공지사항(Notice)`: `게시글 ID`, `관리자 ID`, `제목`, `내용`, `조회수`, `작성일`, `상단 고정 여부`
- **사용자 스토리**
    - "나는 사용자로서, 이번 추석 연휴 배송 일정이 어떻게 되는지 공지사항을 통해 확인하고 싶다."
- **완료 조건**
    1. 공지사항 목록에서는 제목, 작성일, 조회수가 표시되어야 한다.
    2. 중요 공지사항은 목록 상단에 고정하는 기능이 있어야 한다.
    3. 사용자는 제목과 내용으로 공지사항을 검색할 수 있어야 한다.

### 4.8 회원/마이페이지

### 4.8.1 회원 정보 및 주문 내역 관리

- **상세 설명**: 사용자가 자신의 개인 정보, 주문 기록, 활동 내역 등을 한곳에서 확인하고 관리할 수 있는 개인화된 공간입니다.
- **필요 데이터**
    - `회원(User)`: `회원 ID`, `이메일`, `암호화된 비밀번호`, `이름`, `연락처`, `보유 포인트`
    - `배송지(Address)`: `배송지 ID`, `회원 ID`, `수취인명`, `주소`, `연락처`, `기본 배송지 여부`
    - `주문(Order)`: `주문 ID`, `회원 ID`, `주문 정보` (요약)
    - `리뷰(Review)`: `리뷰 ID`, `회원 ID`, `리뷰 내용` (요약)
- **사용자 스토리**
    - "나는 이사를 가서 배송지 주소를 변경하고, 최근 3개월간 내가 무엇을 주문했는지 목록을 확인하고 싶다."
- **완료 조건**
    1. 회원 정보 수정 시, 현재 비밀번호를 입력해야만 변경이 가능해야 한다. (보안)
    2. 주문 내역은 최근 1개월, 3개월, 6개월 등 기간별로 조회할 수 있어야 한다.
    3. 각 주문 내역에서는 주문 상품, 결제 금액, 배송 상태 등의 상세 정보를 확인할 수 있어야 하며, 해당 주문에 대해 '리뷰 작성', '주문 취소', '반품 신청' 등의 액션을 바로 취할 수 있어야 한다.
    4. 자신이 작성한 리뷰 목록과 적립/사용한 포인트 내역을 조회할 수 있어야 한다.

### 4.9 관리자 페이지

### 4.9.1 콘텐츠 및 상품/재고 관리

- **상세 설명**: 사이트 운영자가 웹사이트의 전반적인 콘텐츠와 상품, 재고를 효율적으로 관리할 수 있는 백오피스 기능입니다.
- **필요 데이터**
    - `관리자(Admin)`: `관리자 ID`, `권한 등급`
    - `배너(Banner)`, `공지사항(Notice)`, `상품(Product)`, `상품 옵션(ProductOption)` 등 관리 대상 모든 데이터
- **사용자 스토리**
    - "나는 운영자로서, 새로운 여름 시즌 상품을 등록하고, 품절된 상품의 재고를 100개 추가하고, 메인 화면의 광고 배너를 새로운 이벤트 배너로 교체하고 싶다."
- **완료 조건**
    1. **콘텐츠 관리**: 광고 배너, 공지사항, FAQ 등을 등록/수정/삭제(CRUD) 할 수 있어야 한다.
    2. **상품 관리**: 상품의 카테고리, 이름, 가격, 설명, 이미지 등을 등록하고 수정할 수 있어야 한다.
    3. **재고 관리**: 각 상품(옵션별)의 재고 수량을 직접 수정할 수 있어야 하며, 변경 이력(로그)이 기록되어야 한다.

### 4.9.2 신고 처리 및 알림 기능

- **상세 설명**: 사용자로부터 접수된 신고를 처리하고, 마케팅 또는 정보성 알림을 사용자에게 발송하는 기능입니다.
- **필요 데이터**
    - `리뷰 신고(ReviewReport)`: `신고 ID`, `처리 상태`
    - `알림(Notification)`: `알림 ID`, `제목`, `내용`, `발송 대상 조건`, `발송일`
- **사용자 스토리**
    - "나는 관리자로서, 신고된 리뷰 목록을 확인하고 부적절한 내용을 블라인드 처리하며, 모든 회원에게 '블랙프라이데이 세일' 시작을 알리는 푸시 알림을 발송하고 싶다."
- **완료 조건**
    1. 신고된 리뷰나 게시글을 확인하고 '블라인드', '정상', '삭제' 등의 상태로 처리할 수 있는 인터페이스가 있어야 한다.
    2. 알림 발송 시, 전체 사용자 또는 특정 등급의 사용자 등 타겟을 지정하여 이메일과 푸시 알림을 보낼 수 있어야 한다.
    3. 발송된 알림의 성공/실패 여부를 확인할 수 있는 발송 결과 리포트 페이지가 제공되어야 한다.

## 5. 비기능 요구사항

- 위의 프로젝트의 목표를 포함하고 있습니다.

### 5.1 성능

- 목표 : 목록/검색은 **대부분 0.2초 이내**, 주문 생성은 **1초 이내** 처리.
- 측정 : 서버 처리시간(p50/p95/p99)과 브라우저 첫 응답(TTFB)을 측정.
- **기준(숫자)**
    - 목록/검색 API: **p50 ≤ 80ms, p95 ≤ 200ms, p99 ≤ 350ms**
    - 브라우저 체감(TTFB): **p95 ≤ 300ms**
    - 주문 생성(결제 승인 제외): **p50 ≤ 120ms, p95 ≤ 1,000ms, p99 ≤ 1,500ms**
- **조건/가정**: 상품 10만 개, 동시 조회 200RPS / 주문 100TPS 상황에서도 위 숫자 유지.
- **패스 기준**: 위 숫자를 지키고, 서버 오류(5xx)가 **0.1% 이하**면 통과.

### 5.2 안정성/가용성

- 목표 : 한 달 가동률 **99.9%**, 동시에 몰려도 **재고가 틀리지 않기**.
- **재고 정확성(오버셀 방지)**: 같은 상품(SKU)에 **초당 100건 주문**이 들어와도 **재고 초과 판매 0건**.
- **문제 대비**: 실패 시 자동 재시도(최대 3회), 일정 시간 후 중단(타임아웃 2초), 회로차단기(Circuit Breaker)로 장애 전파 막기.
- **결제 실패 처리**: 결제가 실패/지연되면 주문 취소 + 재고 예약 해제 + 쿠폰/포인트 되돌리기(보상 처리).
- **데이터 보호**: 매일 백업, 가능하면 시점복구(PITR) 사용.
- **패스 기준**: 결제 지연/오류를 일부러 만들어도 **주문/재고 데이터가 틀어지지 않으면** 통과.

### 5.3 보안

- **전송 구간**: **HTTPS(TLS1.2+)** 필수. 가능하면 HSTS도 적용.
- **로그인/권한**: **JWT**(짧게 쓰는 액세스 토큰 + 리프레시 토큰) 사용, 사용자/관리자 권한 구분.
- **입력 검증**: 스크립트 주입(XSS), SQL 주입 방어. 파일 업로드는 확장자/용량 제한.
- **비밀 관리**: 환경변수/시크릿 매니저 사용. 로그에는 개인정보(PII)를 마스킹.
- **감사 로그**: 관리자가 한 중요한 변경은 **누가/언제/무엇을** 남겨 1년 이상 보관.
- **패스 기준**: 주요 보안 점검(OWASP Top10)에서 **치명/높음 위험 0건**.

### 5.4 확장성 → 선택

- 목표: 읽기는 **캐시/복제**로 쉽게 늘리고, 서비스는 **나중에 분리해도 무리 없게**.
- **방식**: 처음엔 한 덩어리(모놀리식)로, 이후 **카탈로그/주문/결제 게이트웨이**로 단계 분리.
- **데이터 연동**: 서비스 간에는 **이벤트(Outbox/Event)** 로 느슨하게 연결.
- **패스 기준**: 트래픽을 **2배**로 올려도 성능 저하가 **10% 이내**면 통과.

### 5.5 관측성

- **로그**: **JSON** 형태, 요청마다 **traceId** 붙이기, 개인정보는 마스킹, 30~90일 보관.
- **지표**: 응답속도(p50/p95/p99), 오류율, **장바구니→결제 전환율**, 재고 충돌률, 오버셀 발생 건수.
- **트레이싱**: 결제/배송 같은 외부 연동은 **따로 표시**해서 어디서 느린지 보이게.
- **알람**: 성능/SLA 위반, 오류 급증, 외부 연동 실패율 상승 시 즉시 알림.
- **대시보드**: 홈/검색/주문/결제/재고로 판넬을 나눠 한눈에 보기.

### 5.6 유지보수성

- **코드 기준**: 단위 테스트 커버리지 **60%+**(도메인 규칙은 80% 권장).
- **문서화**: **OpenAPI(Swagger)** 자동 생성, 변경 시 버전/변경내역 남기기.
- **배포**: **롤링** 또는 **블루/그린**. DB 스키마 변경은 가능한 **호환성 유지**.

### 5.7 용량/한도 → 선택

- **호출 제한**: 주문 생성 API는 사용자별 **분당 10회**, 리뷰 업로드는 **시간당 20회**.
- **봇 방어**: 글쓰기/중요 API에 레이트 리미트, 필요 시 캡차 적용.
- **저장소**: 이미지는 S3 같은 오브젝트 스토리지, **썸네일 미리 생성**.

### 5.8 복구/백업 → 선택

- **백업**: DB **매일 1회 스냅샷** + 트랜잭션 로그 **7일 보관**.
- **복구 목표**: 데이터 손실(RPO) **15분 이내**, 서비스 복구(RTO) **60분 이내**(개인 프로젝트 기준).
- **연습**: 분기마다 **복구 리허설**(샘플 데이터로 확인).

### 5.9 테스트/검증

- **성능 테스트**: k6로 조회 **200RPS**, 주문 **100TPS** 부하 테스트.
- **신뢰성 테스트**: 결제 지연/오류를 일부러 넣어 **보상 처리(SAGA)** 가 제대로 되는지 확인.
- **보안 테스트**: 자동 스캐너 + 체크리스트로 기본 취약점 점검.
- **릴리즈 보류 기준**: 위 핵심 지표가 **10% 이상 악화**되면 배포 보류.
