# 상태 다이어그램

### 3.1 주문 상태
- 주문이 생성된 후 결제, 배송을 거쳐 완료되거나 취소/반품되기 까지의 전체 핵심 흐름을 정의한다.
```mermaid
stateDiagram-v2
  [*] --> CREATED: 주문서 생성
  CREATED --> PENDING_PAYMENT: 결제창 이동
  PENDING_PAYMENT --> PAID: 결제 성공(Webhook)
  PENDING_PAYMENT --> PAYMENT_FAILED: 결제 실패/사용자 취소
  PENDING_PAYMENT --> CANCELED: TTL(10m) 만료 스케줄러
  
  PAID --> PREPARING_SHIPMENT: 피킹/패킹 시작
  PAID --> CANCELED: 사용자 취소(배송 전)
  
  PREPARING_SHIPMENT --> SHIPPED: 운송장 등록
  SHIPPED --> DELIVERED: 배송완료 콜백/폴링
  
  DELIVERED --> RETURN_REQUESTED: 반품 신청
  RETURN_REQUESTED --> RETURNED: 반품 완료
  
  PAYMENT_FAILED --> [*]
  CANCELED --> [*]
  RETURNED --> [*]
  DELIVERED --> [*]: 정상 종료
```

### 3.2 결제 상태
- 결제 요청이 시작되어 카드사 승인, 실제 매입(정산)까지 이어지는 금융 트랜잭션의 상세 상태를 모델링한다.
```mermaid
stateDiagram-v2
  [*] --> INITIATED: 결제 시작
  INITIATED --> AUTHORIZED: 카드 승인
  INITIATED --> FAILED: 승인 실패
  INITIATED --> CANCELED: 유저 취소
  
  AUTHORIZED --> CAPTURED: 매입/정산 확정
  AUTHORIZED --> FAILED: 매입 실패
  
  CAPTURED --> REFUNDED: 전액/부분 환불
  
  FAILED --> [*]
  CANCELED --> [*]
  REFUNDED --> [*]
  CAPTURED --> [*]: 정상 종료
```

### 3.3 재고 예약 상태
- 주문 시 재고를 임시 선점(예약)했다가 결제 결과에 따라 확정하거나 해제하는 짧은 생명주기를 정의한다.
```mermaid
stateDiagram-v2
  [*] --> RESERVED: 주문 생성 시 재고 예약
  RESERVED --> CONFIRMED: 결제 성공
  RESERVED --> RELEASED: 결제 실패/취소
  RESERVED --> RELEASED: TTL 만료(10분)
  
  CONFIRMED --> [*]
  RELEASED --> [*]
```

### 3.4 배송 상태
- 결제가 완료된 주문 상품이 출고 준비부터 고객에게 전달되기까지의 물리적인 배송 과정을 추적한다.
```mermaid
stateDiagram-v2
  [*] --> READY: 출고 준비
  READY --> IN_TRANSIT: 운송장 등록(출고)
  IN_TRANSIT --> DELIVERED: 배송완료
  
  DELIVERED --> [*]
```

### 3.5 리뷰 운영 상태
- 리뷰 작성 가능 조건부터 작성 후 수정, 신고, 블라인드 처리 등 운영 관점에서의 콘텐츠 상태 변화를 정의한다.
```mermaid
stateDiagram-v2
  [*] --> ELIGIBLE: 리뷰 작성 가능 (배송완료 + 7일, 미작성)
  ELIGIBLE --> WRITTEN: 작성 완료
  
  WRITTEN --> EDITED: 수정됨(본문/사진 변경)
  WRITTEN --> BLINDED: 신고/정책 위반 블라인드
  EDITED --> BLINDED: 신고/정책 위반 블라인드
  
  BLINDED --> WRITTEN: 관리자 블라인드 해제
  
  WRITTEN --> [*]: 삭제
  EDITED --> [*]: 삭제
  BLINDED --> [*]: 삭제
```

### 3.6 배너 라이프 사이클
- 관리자가 등록한 배너가 설정된 노출 기간과 활성 상태에 따라 어떻게 사용자에게 보여지는지를 정의한다.
```mermaid
stateDiagram-v2
  [*] --> INACTIVE: 배너 등록
  INACTIVE --> ACTIVE: 활성화 + 기간 시작
  
  ACTIVE --> INACTIVE: 관리자 비활성화
  ACTIVE --> EXPIRED: 기간 종료
  
  EXPIRED --> [*]
  INACTIVE --> [*]: 삭제
```

### 3.7 반품 처리 상태
- 사용자가 반품을 요청한 시점부터 상품 회수, 검수, 그리고 최종 환불 완료까지의 복잡한 과정을 모델링한다.
```mermaid
stateDiagram-v2
  [*] --> REQUESTED: 사용자 반품 신청
  REQUESTED --> APPROVED: 관리자 반품 승인
  REQUESTED --> REJECTED: 관리자 반품 거부 (정책 위반)
  
  APPROVED --> COLLECTING: 수거 지시 (택배사 연동)
  COLLECTING --> IN_TRANSIT: 상품 수거 완료
  IN_TRANSIT --> RECEIVED: 물류센터 입고
  
  RECEIVED --> INSPECTING: 상품 검수 시작
  INSPECTING --> COMPLETED: 검수 통과 (환불 처리 트리거)
  INSPECTING --> REJECTED: 검수 실패 (반품 불가, 사용자에게 반송)

  REJECTED --> [*]
  COMPLETED --> [*]
```

### 3.8 문의 처리 상태
- 고객의 문의가 접수된 후, 담당자가 배정되고 답변이 완료되어 종결되기까지의 고객 서비스 티켓 흐름을 정의한다.
```mermaid
stateDiagram-v2
  [*] --> NEW: 사용자 문의 등록
  NEW --> OPEN: 담당자 확인/배정
  
  OPEN --> PENDING_CUSTOMER: 담당자가 고객에게 추가 정보 요청
  PENDING_CUSTOMER --> OPEN: 고객 답변 등록
  
  OPEN --> RESOLVED: 담당자 최종 답변 완료
  RESOLVED --> CLOSED: 사용자 해결 확인
  RESOLVED --> CLOSED: 자동 종결 (답변 후 7일 경과)
  
  CLOSED --> [*]
```
